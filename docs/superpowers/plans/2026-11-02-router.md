# Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `run_agent(model="auto")` picks the real endpoint for a job from a d3-scored brief and a calibrated scorecard, queues it with every other job through a database-backed, session-counting admission gate, records why, and learns in batch passes over logged evidence; a second MCP server and three CLI commands control and inspect it.

**Architecture:** A `backend: router` entry in `models.yaml` makes dispatch do one extra step (resolve brief → d3 scores → live facts → shortfall selection → enqueue on the chosen real endpoint); from admission on the job is an ordinary job. Admission counts sessions (slots, or pool tokens ÷ window) and lives in the SQLite file so every server process shares it. The scorecard is rows (endpoint name × served id) whose cells are derived by an initiated pass over logged evidence (probe results, gates, verdicts). New code lives in `src/localagents/router/`; `registry.py`, `server.py`, `runner.py`, `status.py`, `db.py` and `__init__.py` are touched at named seams.

**Tech Stack:** Python 3.12, sqlite3 (WAL, `BEGIN IMMEDIATE`), httpx, the existing FastMCP server pattern (`mcp.tool()`), pytest. The d3 server command needs the `router` extra: `torch`, `transformers==5.17.0` (what `vllm-sr/d3-mini` loads with `trust_remote_code=True`).

**Spec:** `docs/superpowers/specs/2026-11-02-router-design.md` at fddf508 or later (every § below refers to it). The calibration SET is its own spec; this plan builds the runner and ships a minimal built-in set so the gate and the runner are testable.

**Order:** three phases, by the operator's call: infrastructure first (Tasks 1–5: a running d3, the router entry, scoring through the C&C server, the CLI), then calibration (Tasks 6–9: scorecard store and pass, capacity, the runner), then routing (Tasks 10–14). Each phase ends with something the operator can touch. Reviews from 2026-11-02 (Opus design, Qwen plan, DeepSeek schema) are folded.

## Global Constraints

- Nothing from the operator's fleet in package code, defaults, README or the example config (no `ai1`, `dgx*`, `10.0.0.*`, model file paths). Fixtures under `tests/fixtures/router/` are the only captured data and are scrubbed.
- A worktree checkout never opens the default state dir: every lane sets `XDG_STATE_HOME`, `LOCALAGENTS_DB` and `LOCALAGENTS_CONFIG` (`tests/router/conftest.py` sets all three like `tests/conftest.py`). Scratch under `t/`, never `/tmp`. No `git stash`.
- The router is never on the wire (§2, §4): no proxy, one decision per job, the session's requests go to the chosen row.
- Only `decision_url` is required on the router entry (§12). Constants named in this plan (`tolerance=0.5`, `divert_after_min=10`, `THRESHOLDS`, `ACCEPT_RATE`, `MIN_COUNT`, weights, band tables, prior curves) are module constants a later calibration spec may revise; each is defined once and imported.
- Schema: one new step `_V10`, plain `CREATE`, every key column `NOT NULL`, every reference declared, `CHECK` on every status column (§13). `SCHEMA_VERSION` becomes 10.
- Every router error returned from a tool is a dict with `error` and `message` like `ModelUnavailable.to_dict()`, never a raised exception. d3 down or slow is `model_unavailable` (§4), not a new error name.
- No module writes a scorecard cell except the pass (§8).
- Public prose (README row, `docs/router.md`): no "X, never Y" slogans, no bold-label inventory paragraphs.

## Review Focus

1. **Two server processes admit into the last session at once.** Exactly one admits. Task 11 `test_two_connections_race_for_one_session`.
2. **The owning server of a queued head job exits.** Another process skips the stale entry and marks the job lost; the endpoint is not blocked. Task 11 `test_stale_owner_entry_is_skipped_and_marked_lost`.
3. **A pointer brief whose file is missing.** `brief_unresolved`, no job. Task 3 `test_resolve_brief_missing_file_is_an_error`; Task 12 `test_run_agent_auto_brief_unresolved_creates_no_job`.
4. **A served id changes under an endpoint, then changes back.** New row, uncalibrated, filtered; the old row archived; the revived row routable again. Task 6 `test_served_id_change_archives_and_return_revives`.
5. **d3 answers with every axis below threshold.** All surviving rows differ only by penalties, the tie-break decides, the ticket lists every axis undetermined, a later verdict adds no observation. Task 10 `test_all_undetermined_falls_to_tie_break`; Task 13 `test_verdict_adds_no_observation_for_undetermined_axes`.
